Prova dell'11 febbraio 2025

Aggregazione dei criteri

Configurazione e modalità di consegna


Create sulla macchina Linux host una cartella esame e all'interno di quella il Vagrantfile e una gerarchia standard di cartelle e file Ansible per generare le VM, configurarle, e trasferirvi i file necessari.

Per consegnare, create un archivio con nome MATRICOLA.tar.gz , in cui MATRICOLA sia il vostro numero su 10 cifre, e il tipo di file sia coerente con l'estensione, e inseritevi la cartella esame (e ovviamente tutto ciò che contiene).

Solo questo archivio deve essere consegnato via EOL. La struttura dell'archivio e la correttezza dei nomi saranno valutate.


Contesto dell'esercizio

Si consideri l'infrastruttura in figura con una rete di client "C", un router "R" e una rete di server "S".

Lo scenario di utilizzo prevede che gli utenti possano utilizzare i Client per richiedere l'esecuzione di programmi sui Server.

Per semplicità, si svolgano i test attivando due server e un client, ma gli script devono essere progettati in modo da funzionare anche per un numero arbitrario di client e server funzionanti.



Di seguito sono dettagliate le attività da svolgere.




Rete e servizi da predisporre

R deve avere le seguenti caratteristiche
    • indirizzo statico 172.21.21.1/24 su NET1
    • indirizzo statico 172.22.22.1/24 su NET2
    • eroga via DHCP ai Client indirizzi appartenenti alla sottorete 172.21.21.128/25
    • eroga via DHCP ai Server indirizzi appartenenti alla sottorete 172.22.22.192/26

Ci deve essere instradamento tra i Client  e i Server

I soli sistemi Client e Server devono essere configurati per il login centralizzato via LDAP. Il directory server è in esecuzione sul Router. 

Si utilizzi Ansible per

  • inserire nella directory un gruppo demo  con id=10000
  • inserire nella directory un utente exam con id=10001 e membro del gruppo demo
  • creare sui  Client e Server la home /home/exam con permessi ristretti al solo utente proprietario
  • installare le chiavi appropriate per consentire a exam il login senza password dai Client ai Server (si sottolinea l'importanza di creare directory e file sempre coi permessi più restrittivi)
Sul Router il demone di logging deve essere configurato per scrivere i messaggi etichettati local6.info nel file /var/log/req.log.

Sui  Client il demone di logging deve essere configurato per scrivere i messaggi etichettati local6.warn nel file /var/log/ans.log.

Sui  Server deve essere installato l'agent SNMP accessibile dal Router.



Richiesta esecuzione


Si realizzi uno script /usr/local/bin/do.sh collocato sui Client ed eseguibile unicamente dai membri del gruppo demo, che accetti come parametro  una stringa senza caratteri speciali, che rappresenta un nome di comando.

Lo script

  • invia al Router via syslog un messaggio etichettato local6.info nel formato _IPC_UTENTE_COMANDO_ essendo
    • IPC l'indirizzo del Client su cui è in esecuzione lo script
    • UTENTE il nome dell'utente che sta eseguendo lo script
    • COMANDO la stringa ricevuta come parametro

  • dopo 10 secondi, controlla le ultime 20 righe del file /var/log/ans.log 
  • se tra queste trova una riga in formato _IPS_UTENTE_COMANDO_ nella quale
    • i valori di UTENTE e COMANDO devono coincidere esattamente con quelli inviati al Router
    • IPS sarà l'indirizzo di un Server, scelto dal Router e comunicato in questo modo al Client
  • allora lo script deve 
    • creare nella home dell'utente su Client una directory con nome del tipo YYYYMMDDhhmmss (ad esempio se l'esecuzione avviene il 20 marzo 2025 alle 11:22:33, sarà 20250320112233)
    • eseguire via ssh sul Server specificato (IPS) il programma /usr/local/bin/COMANDO, ridirigendo rispettivamente output e errori sui file COMANDO.out e COMANDO.err nella directory creata



Individuazione del server


Uno script /bin/dispatch.sh dovrà essere disponibile sul Router , eseguibile solo dall'utente root

Lo script deve essere avviato automaticamente al boot e riavviato in caso di terminazione per qualsiasi causa.

Lo script resta in attesa di nuove righe in /var/log/req.log

Per ogni riga, estrae i dati da _IPC_UTENTE_COMANDO_  e avvia questa procedura:

  • Interroga via SNMP con la massima rapidità possibile tutti i Server dello spazio di indirizzi teoricamente a loro assegnato. Gli agent SNMP devono essere configurati per consentire allo script di verificare:
    • se esiste sul Server il programma eseguibile /usr/local/bin/COMANDO
    • se esiste sul Server il file che consente a UTENTE di autenticarsi via SSH (ignorando il contenuto, ma ricordando i vincoli di permessi)
  • Tra i server che rispettano i requisiti sopra esposti, il Router ne sceglie uno casualmente (hint: man shuf) e invia al client IPC  un messaggio via syslog etichettato local6.warn, contenente l'indirizzo del Server scelto e gli altri dati nel formato che il Client si aspetta come descritto in precedenza
