Prova proposta il 28 ottobre 2025

Aggregazione dei criteri

Contesto dell'esercizio

Si consideri l'infrastruttura in figura con due reti NET1 a NET2 a cui sono rispettivamente connessi client Ci e due server S1 e S2 che operano per garantire continuità di esercizio in caso di guasto.



Lo scenario di utilizzo prevede che gli utenti possano utilizzare indifferentemente qualsiasi Client per connettersi a un server ove svolgere una varietà di elaborazioni. I dati sui Server quindi devono essere sincronizzati ad ogni termine della sessione di lavoro.

Per semplicità, si svolgano i test attivando due client, e come descritto nel seguito creando un utente, ma gli script devono essere progettati in modo da funzionare anche per un numero arbitrario di client e di utenti.

Di seguito sono dettagliate le attività da svolgere.



Rete e servizi da predisporre

R1 deve avere le seguenti caratteristiche
    • indirizzo statico 192.168.200.126/25 su NET1
    • indirizzo statico 172.20.20.6/29 su NET2
    • eroga via DHCP ai Client indirizzi nel range equivalente alla sottorete 192.168.200.0/26

S1 deve avere indirizzo statico 172.20.20.1/29 su NET2

S2 deve avere indirizzo statico 172.20.20.2/29 su NET2

Deve essere garantito l’instradamento tra i Client e i Server.

I soli sistemi Client e Server devono essere configurati per il login centralizzato via LDAP. Il directory server è in esecuzione su R1. 

Si curino gli scambi chiavi necessari ai trasferimenti dati richiesti dagli script.

Si configurino gli agent dei Server per consentire la rilevazione del parametro indicato nello script login.sh

 

Script

---------------------------------------------------------------------------------------
Si realizzi uno script /usr/bin/addldapuser.sh collocato sul Router
---------------------------------------------------------------------------------------

Lo script può essere eseguito dall’amministratore, in presenza di un utente, per generare account.

  • Riceve sulla riga di comando lo username; se il parametro non è composto da sole lettere minuscole, o rappresenta un utente già esistente in LDAP, termina.

  • Chiede interattivamente una password, ripetendo la richiesta se la stringa inserita è più corta di 10 caratteri; se la stringa inserita è vuota, termina.

  • Inserisce l’utente in LDAP

    • creando anche un gruppo omonimo

    • scegliendo il più basso id numerico disponibile ma comunque mai inferiore a 5000

    • settando la password al valore letto in precedenza

    • impostando la home a /home/USERNAME

    • impostando la shell a /bin/login.sh

    • impostando l’attributo description al valore sync

  • Si collega via SSH ai due server per creare la home directory del nuovo utente

  • Crea una coppia di chiavi SSH

    • la chiave privata deve essere protetta dalla password inserita in precedenza e stampata a monitor per poter essere copiata dall’utente, ad esempio su un dispositivo USB;

    • la chiave pubblica viene copiata sui due Server nella posizione opportuna per consentire all’utente il login senza password dai Client

    • cancella i file con le chiavi dal Router

---------------------------------------------------------------------------------------
Si realizzi uno script /bin/login.sh collocato sui Client e sui Server
---------------------------------------------------------------------------------------

Lo script funziona come un “wrapper” della shell: quando un utente effettua il login, lo script esegue prima una predisposizione dell’ambiente, poi avvia una sessione interattiva per l’utente, e quando questa viene chiusa esegue compiti di sistemazione, prima di terminare. In dettaglio:

  • Se rileva di trovarsi su di un Server, lancia immediatamente /bin/bash

  • Se rileva di trovarsi su di un Client

    • Legge la entry LDAP dell’utente e se nell’attributo description trova un valore diverso da sync termina

    • Imposta l’attributo description al valore busy

    • Se non esiste la home dell’utente, la crea e vi entra

    • Rileva via SNMP dai due server un parametro così calcolato: ((carico medio nell’ultimo minuto) moltiplicato per (percentuale di RAM occupata))

    • Esporta la variabile BESTSERVER inizializzata con l’indirizzo del server che tra i due presenta il valore più basso di tale parametro

    • Lancia /bin/bash (si supponga a questo punto che l’utente possa copiare la propria chiave privata o usarla direttamente dal drive USB, per collegarsi al server migliore; questo aspetto non deve essere svolto come esercizio)

    • Quando la shell termina, Imposta l’attributo description al valore presente in BESTSERVER

  •  



---------------------------------------------------------------------------------------
Si realizzi uno script /sbin/sync.sh collocato sui Server ed eseguibile solo da root
---------------------------------------------------------------------------------------

Lo script deve essere eseguito ogni 5’ ogni giorno dalle 5:00 alle 23:00 per sincronizzare i dati eventualmente modificati su di un server durante una sessione di lavoro

  • Estrae tutte le entry LDAP per cui description ha come valore l’indirizzo del Server diverso da quello su cui è in esecuzione

  • Per ognuna

    • imposta description al valore busy

    • trasferisce i dati dalla home dell’utente sul server remoto alla home locale

    • imposta description al valore sync
