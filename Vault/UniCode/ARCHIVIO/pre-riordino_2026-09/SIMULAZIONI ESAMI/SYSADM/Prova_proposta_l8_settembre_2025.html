Prova proposta l'8 settembre 2025

Aggregazione dei criteri

Configurazione e modalità di consegna

Create sulla macchina Linux host una cartella 2025-09-08 e all'interno di quella il Vagrantfile e una gerarchia standard di cartelle e file Ansible per generare le VM, configurarle, e trasferirvi i file necessari.

Per consegnare, create un archivio con nome MATRICOLA.tar.gz , in cui MATRICOLA sia il vostro numero su 10 cifre, e il tipo di file sia coerente con l'estensione, e inseritevi la cartella 2025-09-08 (e ovviamente tutto ciò che contiene).

Solo questo archivio deve essere consegnato via EOL. Nome, formato, struttura e contenuto dell'archivio saranno valutati.

 

Contesto dell'esercizio

Si consideri l'infrastruttura in figura con due reti NET1 a NET2 a cui sono rispettivamente connessi client Ci e un server S1. Le due reti sono connesse attraverso i router R1 e R2, che instradano il traffico, e operano in “parallelo” per garantire continuità di esercizio in caso di guasto.


Lo scenario di utilizzo prevede che gli utenti possano utilizzare indifferentemente qualsiasi Client (ma non più di uno contemporaneamente) per svolgere una varietà di elaborazioni, utilizzando il Server come appoggio per i propri dati, che quindi devono essere sincronizzati ad ogni inizio/fine della sessione di lavoro.

Per semplicità, si svolgano i test attivando due client, e come descritto nel seguito creando un utente, ma gli script devono essere progettati in modo da funzionare anche per un numero arbitrario di client e di utenti.

Di seguito sono dettagliate le attività da svolgere.

Rete e servizi da predisporre

 

R1 deve avere le seguenti caratteristiche
    • indirizzo statico 172.21.0.1/16 su NET1
    • indirizzo statico 172.22.0.1/29 su NET2
    • eroga via DHCP ai Client indirizzi nel range equivalente alla sottorete 172.21.64.0/18

R2 deve avere le seguenti caratteristiche
    • indirizzo statico 172.21.0.2/16 su NET1
    • indirizzo statico 172.22.0.2/29 su NET2
    • eroga via DHCP ai Client indirizzi nel range equivalente alla sottorete 172.21.128.0/18

I Router non devono informare i Client e il Server delle regole di instradamento reciproco.

Sui Router deve essere installato l'agent SNMP configurato per consentire il controllo specificato nello script /usr/sbin/route.sh

S1 ha indirizzo statico 172.22.0.3/29

I sistemi Client e Server devono essere configurati per il login centralizzato via LDAP. 

Il directory server è in esecuzione su S1. 

Si generi una coppia di chiavi SSH.

Si utilizzi Ansible per creare nella directory LDAP un utente con cui fare i test, come da specifiche:

    • uid = prova , id numerico 12345
    • membro del gruppo omonimo (da creare con uguale id numerico)
    • home = /home/prova
    • shell = /bin/inout.sh
    • attributo description impostato al valore (stringa) never
    • attributo gecos impostato alla chiave pubblica SSH pre-generata

Si configuri il Server in modo che esista la home dell’utente prova e contenga nella posizione corretta le chiavi pubblica e privata pre-generate.

Si configuri il Server per ricevere via syslog i messaggi etichettati local4.info e scriverli nel file /var/log/loginout.log

Script

---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------
Si realizzi uno script /bin/inout.sh collocato sui Client eseguibile da qualsiasi utente
---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------

Lo script funziona come un “wrapper” della shell: quando un utente (chiamiamolo USER) effettua il login, lo script esegue prima una predisposizione dell’ambiente, poi avvia una sessione interattiva per l’utente, e quando questa viene chiusa esegue compiti di sistemazione, prima di terminare. In dettaglio:

  • Legge la entry LDAP di USER

  • Se nell’attributo description trova il valore online, termina, mentre se trova un valore diverso (chiamiamolo TS), stampa a schermo “Last login: TS”, e aggiorna la entry sostituendo il valore corrente con la stringa online

  • Lancia con privilegi di root lo script /usr/sbin/home.sh passando USER come parametro

  • Colloca la chiave pubblica disponibile nella entry LDAP in modo che USER sul Server possa connettersi senza password all’account USER sul Client

  • Invia la stringa _login_USER_IP_ via syslog al Server con etichetta local4.info, essendo IP l’indirizzo del Client

  • Si pone in attesa che nella home compaia un file di nome Sync_Ended e lo cancella

  • Esegue /bin/bash

  • Invia la stringa _logout_USER_IP_ via syslog al Server (come sopra)

  • Sostituisce il valore online dell’attributo description con una stringa che rappresenti la data e ora attuale nel formato “anno-mese-giorno ora:minuto”



---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------
Si realizzi uno script /usr/sbin/home.sh collocato sui Client ed eseguibile solo da root
---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------

Lo script riceve come parametro un nome utente (chiamiamolo USERNAME) e deve garantire che la home dell’utente nella posizione /home/USERNAME esista e abbia permessi corretti (restrittivi) effettuando le eventuali operazioni necessarie .

---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------
Si realizzi uno script /usr/local/bin/homesync.sh collocato sui Server ed eseguibile solo da root

Lo script deve essere avviato automaticamente al boot e riavviato se termina per qualsiasi motivo.
---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------

Lo script si pone in attesa della comparsa di righe nel file /var/log/loginout.log, che saranno nel formato _COMANDO_USER_IP_ e per ognuna:

  • se il COMANDO è login, trasferisce via SSH il contenuto locale della home di USER (file e directory, mantenendo la gerarchia) nella home di USER sul Client IP. Al termine, crea nella home remota un file di nome Sync_Ended

  • se il COMANDO è logout, esegue il trasferimento inverso (senza creare file aggiuntivi)



---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------

Si realizzi uno script /usr/sbin/route.sh collocato sui Client e sul Server ed eseguibile solo da root

Lo script deve essere eseguito automaticamente ogni minuto dalle 8 alle 20 dei giorni feriali.

---------------------------------------------------------------------------------------------
---------------------------------------------------------------------------------------------

Opera come segue:

  • Rileva dalla tabella di instradamento local quale Router viene usato per raggiungere la rete remota (quella dei Server se è in esecuzione su di un Client, o viceversa); se non c’è alcuna rotta definita, sceglie un Router in modo casuale tra R1 e R2

  • Verifica via SNMP se il Router scelto è raggiungibile e se il suo valore impostato in /proc/sys/net/ipv4/ip_forward è uguale a 1 (forwarding attivo)

  • In caso di esito positivo, imposta la rotta verso la rete remota perché passi attraverso tale Router (si evitino duplicazioni nella tabella di instradamento)

  • In caso di esito negativo, imposta la rotta attraverso l’altro Router (si assuma l’ipotesi che non si possa mai verificare il guasto simultaneo dei due Router)
